## What Changed

This slice shipped Pi-shaped raw terminal input subscriptions for live product-TUI extension contexts. Extension command and shortcut handlers can now call `ctx.ui.on_terminal_input(handler)` or `ctx.ui.onTerminalInput(handler)` to observe decoded key strings before the built-in editor handles them. A handler can let the key continue unchanged, consume it, or replace it with different input text; disposers are idempotent, and failing handlers are ignored so a bad extension cannot break prompt entry.

The behavior is live-only. Headless/no-UI contexts return a safe no-op disposer and never call the handler, matching Pi RPC's unsupported interactive-input boundary. Terminal input listeners are cleared with extension chrome on reload/shutdown so stale registrations do not accumulate.

## Boundaries

This slice did not ship full custom editor-component rendering or component-specific input routing. It only exposes the terminal key stream that already reaches the product TUI prompt loop. It also does not archive raw terminal input, does not make the API available in headless execution beyond a no-op disposer, and does not attempt TypeScript source compatibility with Pi extensions.

## Comprehension Check

<details>
<summary>What can an extension handler do with a key?</summary>

It can observe and pass the key through, return `consume: true` to suppress built-in handling, or return `data` to replace the key before normal editor handling continues.

</details>

<details>
<summary>What happens outside the live product TUI?</summary>

`on_terminal_input` / `onTerminalInput` returns an idempotent no-op disposer and the handler is never invoked.

</details>
