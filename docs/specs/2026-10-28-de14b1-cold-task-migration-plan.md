# DE14b1 — Cold task-definition compatibility and migration

## Scope and authority

Implement reservation-time migration for generic private native tasks using one immutable definition catalog per TaskScheduler owner. This is the next bounded increment after delivered DE14a `48fd18796b9ec9b34b08c6e93e1d75bacfc37043` (tree `cd06b06973a634b9441dc4cecb2fceafc449cbee`), not closure of DE14/P06/P07/P26 or the Durable feature. Restore missing/incompatible code by closing the old owner and opening a fresh owner with fitting definitions. Same-owner registry installation/replacement and handover are explicitly later work.

The existing scheduler remains the only reservation/invocation owner. Reuse its Session line, condition, captured definitions, invocation retirement and physical close/lease joins. Add no Storage API, persisted migration-audit/failure document, public generic-task SDK/CLI admission, general registry/settings service, or codec/TaskRecord schema change. Product still constructs only its existing bound generation and model-tool definitions. This child neither migrates those built-in records nor authorizes a custom callback to reinterpret their inputs, checkpoints, catalogs, receipts or outcomes.

## Definition and fit

Add an optional keyword-only synchronous `migrate(input, checkpoint, from_version)` callback to the private Task/define_task surface; preserve capture-before-suspension and immutable per-owner identity. The returned value is an exact dictionary with exactly `input` and `checkpoint`, each in the existing strict JSON domain. Validate/copy both before any candidate install. Pass detached native JSON inputs and no Runtime/Tx/credential/port capability. Migration is trusted pure code: it must not perform external effects. The runtime must reject coroutine/foreign-awaitable results without executing them, following existing initializer cleanup rules. No foreign attribute traversal, callback or reference disposal occurs under the metadata condition.

Keep the actual finite binary64 numeric version ABI, including valid fractional/negative values and numeric equality such as signed zero. Do not impose an integer/safe-ID/positive-version restriction. Fit by existing UTF-16 task-name identity and numeric comparison:

- Equal version: execute the existing path unchanged; never call migrate or rewrite input/checkpoint/version merely because a callback exists.
- Missing definition or current version less than stored: remain live and noninvoked, with truthful missing/stored-newer inspection. Missing code alone never settles a task.
- Current version greater than stored: an eligible generic record may migrate if the captured definition has a migrator. Without one it remains blocked for migration; do not call the initializer as a substitute.

All existing pending/abort/abandon/restart-parked/historical-blocked eligibility and actual model/owner graph guards precede migration. A migrator attached to a model/generation definition does not widen built-in admission; incompatible built-in versions retain their existing refusal. No waiting/sleeping/owned-work readiness support is invented beyond what this scheduler already admits.

## Atomic reservation and failure

For an eligible generic pending task, reread committed authority on the same Session line that will reserve it. Select the already captured definition, run synchronous migration outside the condition while the line remains owned, detach/validate the result, and derive a replacement preserving all other record fields. Then recheck actual close/enable/invocation guards and commit new version/input/checkpoint plus pending-to-running in the single existing transaction. Only a successfully admitted/acknowledged reservation may dispatch the handler; preserve tentative-invocation retirement on any failed admission. Do not release a still-running callback or backend owner because a caller was cancelled.

Preserve ID, kind, conversation/owner/background/abort/abandon fields, tracing links, memos and restart count; preserve existing lifecycle stamping rules. Migration itself is not task progress and does not reset the streak. A successful newer-version migration whose input/checkpoint are structurally unchanged still commits the new version. A valid JSON checkpoint without a usable phase remains subject to the existing subsequent missing-phase fault; it is not retroactively an invalid migration result. Ordinary unchanged/equal-version records and normal fact1/Bfact2 byte paths remain unchanged.

An ordinary migration exception or invalid result records only a bounded volatile `migration_failed` fact for that task and actually installed captured definition. Continue scanning later candidates in the SAME reservation transaction/pass; a later eligible task must be reserved without an unrelated external wake. Do not raise the ordinary callback failure into Session failure, return early with no invocation, or roll back legitimate `_reconciled` writes already staged in that transaction solely because migration failed. If no later candidate is eligible, finish the pass normally and commit any legitimate reconciliation writes. The failed generic task, including version/input/checkpoint/memos/restarts, remains unchanged; failed migration itself creates no durable record or revision. This targeted invariant is not a claim that unrelated reconciliation or successful reservation in the same pass makes no writes.

No arbitrary exception text/input/checkpoint reaches metadata, SDK/CLI JSON, provider wire or public errors. Backend/Session/infrastructure failure still follows the existing transaction/owner failure path, including rollback where no commit occurred; it is not an ordinary migration failure to skip. Preserve control-flow BaseException/cancellation rather than hiding it as a compatibility result.

Remember failure once per task/installed definition for the owner's lifetime; ordinary wakes, repeated resume, inspection, same-task counter reset and unrelated record notifications must not rerun that failed definition. There is no live definition-replacement API in b1. Fresh owner construction starts a new volatile memory and can attempt its fitting definition. Terminal observation and owner close drop remembered failures; retain no historical exception/callback/payload graph. Every failure-memory reader/writer uses the existing condition. Release displaced references outside it. Do not hold that condition while acquiring or awaiting the Session line. An identity-only in-memory failure is not durable proof or a new authorization.

Storage rejection before commit leaves the old version/input/checkpoint authoritative. A real commit followed by acknowledgement loss may leave the new running record even though the caller sees failure: dispatch no handler on the failed acknowledgement, seal/retire using existing failure rules, and let a fresh owner recover actual committed state. Never roll back a real committed winner or synthesize an acknowledgement. Pure migration may run again after an uncommitted attempt; no exactly-once callback claim is made.

## Inspection and public boundaries

Preserve the exact 17-field TaskInspection tree, bounded privacy and terminal/completing code-independent path. The following finite table specifies compatibility/reason before the existing native authority and abort refinements. “Owner” means the new same-owner inspection path with a failure snapshot for the actual captured definition; ordinary callback-free support never claims that history.

| Record / captured definition | Ordinary metadata | Same-owner metadata |
| --- | --- | --- |
| Terminal, regardless of definition | `terminal_readonly` / null | Same; no code or migration lookup |
| Completing, regardless of definition | `unknown` / null | Same; no code or migration lookup |
| Live, support omitted | `unknown` / null | Owner supplies its actual captured support |
| Generic or built-in, definition missing | `unsupported` / `definition_missing` | Same |
| Generic or built-in, current version less than stored | `unsupported` / `stored_version_newer` | Same |
| Generic or built-in, equal version, valid phase (including the existing nondispatchable `blocked` exception) | `supported` / null | Same; no migration lookup/call |
| Generic or built-in, equal version, unusable/unsupported phase | `unsupported` / `unsupported_phase` | Same |
| Generic, current version greater, no migrator | `unsupported` / `migration_failed` | Same; means missing migration capability, not an attempted callback |
| Generic, current version greater, migrator present | `unknown` / `migration_required` | Same before an attempt; `unsupported` / `migration_failed` after remembered failure of this captured definition |
| Built-in generation/model-tool, current version greater, with or without migrator | `unsupported` / `definition_version_mismatch` | Same; callback attachment grants no migration authority |
| Live and restart-parked | Preserve compatibility; use `restart_limit` only if the otherwise final reason is null | Same; `restart_parked` remains true even with a stronger reason |

Thus `definition_version_mismatch` is retired for generic newer-definition cases, not removed from the closed reason vocabulary: it still denotes the built-in refusal. Add exactly `migration_required` and `migration_failed` to `REASONS` and update exact expected sets, not aliases or permissive membership. Existing `_native_details` receipt-repair, abort, format/graph, historical hold and retained-terminate refinements retain their precedence. Parking is checked after those refinements. Potential migration does not test the old checkpoint's phase against the new definition or claim observed failure. Inspection never runs migration or exposes callbacks, errors or task input.

This deliberately changes the delivered `inspection-v1` generic “older” observation. Update `scripts/durable_reference/cases/inspection.mts` so Pi `migration_failed` maps to native `migration_failed`, and update the exact older-case expectation in `tests/durable/test_inspection_comparison.py`, native reason validators and reason documentation. Keep the existing nine-field Pi COMMON task projection distinct from the full 17-field native DTO. Preserve phase identity, ordered members/pins/parents, test IDs, zero-code/read-only and privacy/malformed/semantic-negative assertions; reclose affected manifests and execute fresh evidence with the new declared meaning. Old raw phase results remain evidence for their old source epoch, not proof of the changed meaning. Built-in mismatch controls remain explicit negatives.
Ordinary InspectionSupport remains exact-type and callback-free. It may capture a boolean migrator-presence capability, not an executable callback or fabricated attempt history. Add one private same-owner inspection entry point on TaskScheduler using the existing inspection capture implementation: acquire the Session read line first, snapshot current definition/failure metadata under the existing condition inside that read, then capture the actual record with the immutable snapshot. It must never invoke a migrator. Its bounded failure context is not accepted through the ordinary public support parameter. Detached ordinary inspection without owner failure context can report potential migration but cannot claim a previously attempted failure. Keep this distinction documented and executable; no mutable parallel lifecycle or copied source of durable authority.

Public ProductSession/SDK/CLI signatures, selection/profile/header/workspace/provider/material gates, C1 immutable saved/current catalog, C2 audit nonce and actual receipt identity/first-winner payload/counters remain unchanged. Any-receipt retry fences and fresh-attempt semantics remain separate. Do not use generic migration to repair missing intent, opaque/newer receipts or a blocked historical model-owned state. Existing lease/reentry/wrong-loop/close behavior and private-error translation remain intact.
