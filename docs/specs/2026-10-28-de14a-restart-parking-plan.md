# DE14a: bounded restart parking and same-task reset

This prospective implementation contract is based on delivered C2 commit `06823adb62cedd8ebcde587af5365f6eaff82630`, tree `7c839014e4e52274e54d9038cd040af0a4a62681`, and Pi `2ec55d808d455b1a64a2bf7888198207a096120a`. It is not an implementation or parity-completion claim. Exact source captures and anchors accompany this plan.

## Scope and policy

Implement a host restart ceiling using the existing persisted `TaskRecord.restarts`, existing scheduler host, owner Condition and Session committing line. Parking is derived admission metadata, not a new task state, checkpoint, receipt, audit or persisted setting. Default limit is 5. A surviving `running` row becomes `pending` and increments once during recovery; opening an already pending row does not increment or dispatch. Healthy close keeps the existing count without increment. Existing structurally changed task-state progress, completing and terminal transitions clear the count. Equal state, memo updates, document-only changes and acknowledged retained tool output/details do not clear it.

Use one immutable normalized policy per owner. `TaskScheduler`, product `create`/`open`, and code-free inspection accept `restart_limit` with default 5. The product passes its captured policy to its scheduler and inspection; no mutable mirror or live setter is introduced. Host-policy admission accepts only exact builtin int/float values representable exactly as finite binary64, plus explicit positive float infinity as the unlimited sentinel. Valid values at least 1 are floored; bool, subclasses, nonnumbers, NaN, negative infinity, values below 1 and out-of-domain integers use default 5 without conversion exceptions. This is a local policy domain, not a stored-counter change or a safe-ID cap: `2**53+1` and `10**5000` default, while `2**1000` and the floor of the maximum finite float remain valid. Infinity is exposed as null, never serialized as a number. CLI `--restart-limit` accepts exactly `Infinity` or JSON-number syntax parsed as finite binary64; overflow-to-infinity, NaN, `inf`, `+Infinity` and `-Infinity` are `invalid_request`. Exponent forms are allowed when finite; finite values below 1 default to 5. All six commands (`start`, `resume`, `inspect`, `authorize-retry`, `adjudicate-interrupted`, `retry-task`) accept this option. CLI numeric text deliberately follows finite binary64 parsing, including its rounding: `9007199254740993` selects the effective limit `9007199254740992`, while the exact raw SDK integer `2**53+1` is out of its typed value domain and defaults to 5. The SDK float representing that rounded binary64 value selects the same limit as the CLI. Document this input-domain difference and compare all three forms in tests; overflow is still rejected and never becomes the unlimited sentinel. A fresh owner can supply a higher limit or Infinity. Policy is neither written to HEADER nor part of stored profile identity. Broad `configure`, live host-setting changes and wake behavior are deferred.

For a live non-abort task, an existing valid finite numeric restart count at or above the effective limit blocks its next dispatch reservation. Missing count does not park. Do not floor, clamp, reinterpret or globally strengthen stored counters: existing finite numeric record ABI remains. Preserve existing fail-closed behavior for invalid records and arithmetic outside the record domain. Terminal/completing read paths remain unaffected. Parking does not cancel an already admitted invocation, implement abort handlers, or change missing-definition/version/phase behavior.

There is no receipt exemption. A valid finite count at the ceiling delays even no-invoke receipt settlement, while preserving the exact actual winner and its counters. Operational parking uses the existing wider record-ABI numeric domain, distinct from the narrower C1 cause-counter validator. Thus valid receipt-bearing live rows with ABI-valid `7.5`, `2**53` or `1e300` park at the default ceiling even though those values are invalid C1 cause counters. After authorized clear, or with an explicitly unlimited owner, the existing receipt-first classifier preserves that actual winner unchanged. Below-limit, missing and malformed-source behavior after admission remains as delivered; receipt-absent public preflight/cause validation is not globally weakened. No floor/clamp or new cause-counter parser is inserted into receipt-first capture. C2 decision-only validated nonce replay remains available and mutation-free. Adjudication does not clear the restart counter. Resetting a counter never authorizes an old unsafe invocation, changes a receipt fence, or converts a historical blocked checkpoint into executable authority. Reset deliberately discards the current restart-streak/budget observation. If an interrupted receipt is first synthesized after clear, the absent current counter becomes explicit null/unknown, never fabricated zero or the discarded previous count. A subsequent genuine crash supplies its actual new count. This is not cumulative history; add no reset audit, second counter or receipt format. Existing saved winners keep every counter byte.

## Controls and ownership

Add a private scheduler same-task retry control distinct from `authorize_retry`. It requires an actually opened healthy owner before any commit; unopened/opening, failed or closing owners refuse before counter mutation, using existing guarded lifecycle authority. Its Session-line primitive rereads the actual task, rejects an unknown task, and removes only `restarts` from a parked live non-abort row. Terminal/completing/nonparked rows are successful no-ops with no task revision. It preserves ID, input, checkpoint, owner/CID, memos, timestamps other than those unavoidably managed by the existing transaction, receipt, progress and audits. After a successful private scheduler retry, enable scheduling even for a no-op, as Pi does. Failed commit never enables. Retain owned/shielded completion through cancellation and close; no enable after a sealed/failed owner.

Expose product `retry_task(task_id, *, selection=None)` and CLI `durable retry-task --target-task ID` as admission-only controls returning a bounded ACK containing task ID and whether the counter was removed. For this command, optional `--task` plus `--resolution-nonce` exclusively identify the existing selected-run authority; neither is the reset target. Preserve other commands' existing argument meanings. They do **not** enable or invoke; the caller explicitly uses existing `resume(selection)`. This deliberate public difference from Pi `retryTask` remains a parent obligation. The command has no nonce because it creates neither a new attempt nor an audit: duplicate calls reread current state and normally return a no-op; after a later independent crash, another call may reset the newly accumulated count. Do not claim historical idempotency across intervening work.

Fresh public reset requires a matching profile and the existing full HEADER/workspace/provider/catalog/selected-run ownership admission. Preserve successor `DurableRunSelection` requirements, the exact saved/current authority checks, and cross-conversation refusal. The target must be the validated selected generation or its actually validated model-owned child; no arbitrary task-ID authority. Reuse selected-run/round checks rather than reconstructing ownership from a caller ID. Private scheduler controls continue to support generic registered tasks. The product reset uses the shared Session-line primitive without the scheduler's enable tail. It neither opens/reconciles a cached unopened scheduler just to reset nor creates an implicit resume. An opened scheduler is paused/drained through existing control ownership before the same-line recheck and mutation. An unreconciled surviving `running` target on a cold/unopened owner refuses `unavailable` with no writes: require explicit resume/recovery first, never ACK a misleading nonparked no-op before its pending recovery increment. Existing profile/selection/ownership refusal precedence remains. Failed/closed/unopened/opening cases use actual guarded lifecycle state, not a second lifecycle flag.

All reset writers, recovery, reservation and result/checkpoint commits serialize on the same Session line. Check current status, abort mark and ownership again there; a snapshot inspected before pause is not mutation authority. Late result, abort or close must not be overwritten by stale reset data. The owner Condition protects scheduler index/lifecycle admission; the immutable policy requires no mutable settings lock. Normalize before entering guarded critical sections. No foreign callback or blocking payload destruction under the Condition. Public errors use existing bounded `DurableProductError` codes (`invalid_request`, `profile_required`, `selection_required`, `incompatible`, `busy`, `closed`, `unavailable`, `foreign_live_task`, `wrong_loop` and `reentrant` as applicable; codes from reused admission/check paths pass through unchanged), with corresponding established CLI exits. Never leak private exception text or flatten an explicit incompatible selection into unavailable.

## Inspection and completion

Expose allowlisted restart count, effective host limit (null means unlimited) and derived parked status in task inspection/CLI JSON. Missing count remains distinct from zero. These are host-policy observations, not stored policy. A code-free store inspection uses its explicit/default policy, labels that effective limit, and does not claim that it knows an unrelated running owner's configuration. Existing more specific blocked/receipt/abort/format/ownership reasons remain available; use `restart_limit` only when it would not erase an existing reason. Public held detection must also recognize the derived parked flag, so resume returns held rather than waiting forever on a task that cannot reserve.

No schema, canonical codec, normal fact1, B/C fact2, receipt carrier, audit namespace or normal request/header byte change is permitted. Inspection must not expose payload, key, prepared intent, credentials or arbitrary exception text. Preserve current retry's ANY-receipt fences and NEW-attempt/nonce semantics separately.
