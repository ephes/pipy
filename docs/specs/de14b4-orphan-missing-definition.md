## Scope and API

Add private `TaskScheduler.orphan_missing_definition(task_id: int) -> Literal["orphaned", "terminal"]` and async `aorphan_missing_definition` with the same argument/result contract. The operation handles only a generic **pending**, unmarked, strict root leaf whose kind has no definition in the current immutable owner generation. It is explicit operator action, never automatic recovery, inspection, or dispatch behavior. No Product/CLI/exported SDK abort API, general registry, handler, migrator, descendant cascade, completing task, active cancellation, restart-abandon budget, or active definition handover is added.

The successful first call returns `"orphaned"` only after ordinary Session commit settlement. A generic already-terminal target returns `"terminal"` without replacing its record, checking current code availability, retiring more documents, or changing revisions. An absent target raises `ValueError("Unknown task")`; it is not success. Reserved targets are refused even when terminal. Existing inspection sees its ordinary terminal outcome; no DTO field, reason enumeration, or readiness claim is added.

The private return value intentionally differs from Pi: Pi `abortTask` returns `"marked"` even when it immediately settles an orphan, then `"terminal"` on repetition. A common reference projection may map this **proved immediate-orphan case only** to native `"orphaned"`; full raw ACKs and records remain retained. Persist the Pi-compatible outcome `{status: "orphaned", reason: "missing_task"}`. Native pre-action inspection's `definition_missing` label remains unchanged.

## Validation, lifecycle, and admission

Use the existing Session ownership machinery, not a new host/lock/queue. Refuse Session reentry first; synchronous calls also refuse execution on an event-loop thread before argument work. Validate the detached ID using the existing exact positive safe-integer validator before an async suspension (no bool/float/subclass coercion). No callback or user-supplied policy is accepted.

Both entry points reach one synchronous owned implementation using an ordinary Session commit; the async path uses existing `owned_call` so cancellation cannot detach its accepted worker. Inside the line callback, inspect Session failure/line sealing, scheduler host closure and `_opened` under the shared condition, using the established failure-before-closed-before-not-open precedence. `_opening` is not an openness predicate. Existing line-entry health/reentry failures retain their types. A healthy not-open owner raises `RuntimeError`; an owner with `_draining` true or `_invocation` non-None raises `RuntimeError("Task scheduler is busy")`. This is a globally quiescent admission gate, not a paused-only API or a wait-for-idle API.

After that gate, fetch the current task from the transaction. Missing is ValueError; any reserved `pi.` kind is `UnsupportedTaskExecution` (deliberately stronger than the current three reserved names, limited to this new control); generic terminal returns the stable no-op above. A nonterminal target must satisfy the strict query below, otherwise `UnsupportedTaskExecution`. Invalid graph observations are refusals; actual backend/record-read failures retain existing Session failure behavior, not a fabricated unsupported result.

Prepare only detached candidate data on the line. After scans and before staging the terminal replacement, repeat health/open/closed and actual activity checks under the condition. This final check is the control's admission point: if service admitted a drain first, refuse with no candidate write. If this control wins, later service admission is a successor waiting for the occupied Session line; it cannot reserve or publish a definition between eligibility and settlement. Do not hold the condition over storage I/O, await, preparation hooks, or user-reference disposal, and do not add a synthetic activity flag. Once admitted, normal Session commit/close rules finish or fail the transaction; a later close/caller cancellation is not a promise of rollback.

Paused owners give deterministic success/no-write tests. Enabled success requires an actual retired/quiescent owner; an already-admitted pass legitimately produces busy refusal. Tests must separately prove each path, without retrying busy as success or assigning internal activity flags. A caller queued behind a held migration is not proof of busy admission: the line job must actually reach its decision point.

## Shared strict eligibility prerequisite, included in this slice

A new private shared query is required; it does **not** exist in delivered code. Both control APIs use this one query and the same commit implementation. Do not substitute scheduler `_owned` (which only examines direct LIVE children), inspection snapshots, cached live indexes, or a fixed-size first page. Do not alter `_owned` or existing dispatch/reconciliation permissions as part of this slice.

Within that actual transaction, read all task and conversation pages to exhaustion using existing typed queries. Build detached per-ID maps from validated records. Reject duplicate/conflicting IDs, inconsistent target-versus-scan observations, nonadvancing/repeated cursors, unresolved ownership endpoints, inconsistent owner/conversation relationships, or ownership cycles. Task owner references must identify a known task in the same conversation; every task's containing conversation must exist; conversation owners must identify an existing task and its actual conversation. Validate the ownership-edge graph, not arbitrary trace/link carriers or conversation history/entry lineage. These additional refusal checks are local to the control, not a global codec/schema tightening or a claim of Pi's general ownership traversal.

The target must have: pending state; `abortRequested == false`; no `abortReason`; no `abandonOnRestart`; no `owner`; a present ownerless containing conversation; no task anywhere with `owner == target.id`, **including terminal and background children**; and no conversation anywhere with `owner.taskId == target.id`, including empty conversations. Additionally refuse if any **other** task is waiting and its `state.on` contains the target ID, regardless of that waiter's owner or background flag. This incoming-dependency check uses the same complete task scan and is deliberately stricter than the Pi leaf path; it does not settle waiters, traverse a general wait graph, or introduce wait-cycle policy. Generic terminal repetition retains its earlier no-op and does not run these pending-target checks. Any `pi.` target is excluded. The kind lookup uses native UTF-16 identity in the one current generation captured on this Session line; it must be absent. A present definition refuses without fitting versions, migration, phase lookup, or callback evaluation. Missing code alone never proves leafhood.

Rejecting both possible first owned edges rules out any downstream owned work behind settled ancestors; it intentionally refuses some cases that Pi's broader ordinary-work traversal accepts. Complete scans and ownership validation belong in the same bounded slice, with large-page and malformed-snapshot tests. This is not a new general ownership API. Background roots and ownerless fork conversations are not themselves excluded; their flags/history remain unchanged when their ownership graph satisfies the strict rule.

A restart ceiling does not authorize or veto this explicit action: a genuinely missing-definition, otherwise eligible generic task may be parked. Preserve the wider existing numeric-record ABI and do not use C1/C2 cause-counter parsing. Unmarked pending records with arbitrary valid finite restart values are handled by the existing terminal conversion. Existing abort/restart/abandon marks are refused rather than upgraded, consumed, or interpreted.

## One atomic settlement, ownership, and observability

Use the current terminal conversion `_state` and Tx task replacement: preserve task ID, conversation, kind/version/input, background, trace/links and other retained fields; replace state with the outcome above, remove live `memos` and `restarts` as existing terminal ABI requires, and let existing Tx timestamp rules determine `endedAt`. Do not manufacture an abort mark, change `abortRequested:false`, rewrite headers/catalogs/nonces/receipts, create a successor, or reset a budget before settlement.

The same real storage commit must include retirement of all current task-scoped documents through existing Tx assembly, including unloaded documents and multiple pages. Task documents are current-only: native document definitions allow rewindable history only for conversation scope. Use the existing backend retirement policy unchanged. Native Memory keeps current materialized state, hides retired documents from current lookup, and supplies no numeric historical reads. SQLite retirement removes revision rows for current-only documents (therefore all target task documents), retaining their retired record metadata; rewindable conversation-document revisions follow existing retention semantics and are untouched by this task action. The control must not directly manipulate history rows, load document values through user tokens, invoke preparers/checkpoint callbacks, or retire conversation/Session/other-task documents. Normal Session publication updates scheduler inspection and evicts a terminal task's failure binding using existing guarded reference disposal outside the condition. Definition generations and restart policy are unchanged.

The complete pinned Pi outcome hook is part of the authority: Harness installs `settleSchedulerOutcome`; scheduler termination calls it after staging the terminal task. In `live.ts`, the tool and compaction branches and the `RUN_TASK_KINDS` generation set are all reserved `pi.` kinds. Every eligible non-`pi.` generic kind returns before `tx.doc`, live-slot cleanup, partial conversion or run termination. Thus this actual installed hook performs no additional transaction read/write for the admitted generic route; no native cleanup counterpart is required for that route. Keep the real Harness hook in the reference producer, rather than replacing it with a no-op or constructing bare Tasks. Harness/root initialization can already create live/inbox state before the action baseline. Built-in cleanup remains excluded, not normalized away; complete raw records and document trajectories must show the absence of additional generic hook effects.

There is no extra explicit enable/resume/notify in this API. A successful task commit retains the existing `_observe` notification: a paused owner stays paused; an enabled owner may subsequently run unrelated eligible work. Therefore the promise is **no target phase/migration/abort handler/provider/tool callback**, not global callback silence on an enabled owner. No-write refusal/terminal/missing paths publish nothing and add no wake. Old immutable inspection/generation snapshots remain unchanged; a new line inspection sees the committed terminal record and retired-document state.

Before storage admission, callback/assembly failure leaves task, documents, revisions and sequence unchanged. A backend error may seal the Session as it does today. With real COMMIT-before-ACK loss, the caller receives the existing failure; it must not report success or automatically retry. After closing/releasing the failed owner and reopening, the saved terminal winner returns `"terminal"` without a second settlement. Async cancellation likewise does not imply rollback: the owned worker is joined and actual stored state is authoritative. Close cannot release the lease ahead of that worker; no helper/finalizer reference is disposed under the condition.
