# DE13c1 interrupted tool continuation

This implementation contract covers recovered execute intents and supported settlement. It does not complete the [DE13/P21 parent obligations](2026-10-19-durable-execution-plan.md): explicit historical blocked-record migration belongs to C2, and operational restart policy belongs to DE14. Implementation requires the delivered DE13b source and public API boundaries to be reread and validated first.

## Admission and recovery ownership

A supported, model-owned execute intent must retain valid saved input, prepared arguments, key, descriptor, workspace, assistant/round/slot and task ownership. With an unchanged catalog, exact saved-safe/current-safe replay retains its existing supported descriptor/version/workspace checks. Otherwise, an intact eligible execute intent settles without invocation when replay is unsafe or fails solely because the current capability is missing or changed. This includes stored-safe/current-missing and stored-safe/current-unsafe. Malformed or unknown saved authority remains held.

Changed or missing current catalogs are admitted by public resume only when every unresolved authority state is an eligible execute requiring no invocation, or a supported settlement with an actual valid receipt. No pre-intent call or persisted provider request that can dispatch removed/changed tools may proceed under this exception. If that closed condition fails, public preflight refuses before scheduler execution or state writes. It must not create a new blocked record or fabricate an intent. If any unresolved intent still requires actual safe replay, a changed whole catalog causes the same preflight refusal even when that intent's own capability is unchanged and only an unrelated tool was removed. In C1, unchanged-safe replay means the entire catalog is unchanged. Restoring the matching catalog remains a valid control. Pre-intent/catalog migration is deferred to C2.

Execution admission, inspection/held classification and public waiting must share this finite disposition, with transaction revalidation before changing state. Preserve foreign-live-task, descendant, abort/background and physical ownership exclusions. The original catalog/provider binding stays immutable. Run-owned header identity excludes only the ordinary admission pointers `initial_entry` and `initial_generation`; all other header fields remain bound, and full product header/initial-root graph validation is unchanged. Subsequent PREPARE_DOC offerings preserve saved order and intersect saved authority with unchanged supported current declarations/descriptors; extra capabilities do not enlarge authority. Cover default catalog, explicit empty tools and CLI no-tools. Explicit new-key retry keeps all existing registration, nonce, receipt and current-authority guards. Provider continuation still requires its existing matching supplied profile; terminal reopen remains auth-free.

## Receipt precedence and historical holds

On supported nonblocked execute/settle paths, an actual valid committed receipt is the first winner and settles unchanged. Any nonempty invalid, opaque or newer receipt fences synthesis. Only receipt absence permits a new interrupted candidate. Validate matching committed progress on the same Session transaction line and retain output, details presence and diagnostics. Invalid or mismatched progress stays held. Missing historical progress means empty output, absent details and unknown attempts. Database visibility after lost callback ACK does not retroactively acknowledge the callback.

All historical blocked states remain held, including uncertain, incompatible, invalid_result and intent-less forms. Any receipt on a blocked task remains an opaque repair fence. C1 does not replace the operator contract: explicit retry remains available only where existing guards permit it. If an older B runtime reads a C1 interrupted receipt and writes blocked/intent-None, C1 preserves that receipt and hold; it does not resume settlement automatically. C2 owns explicit migration/adjudication of these origins, including distinguishing old ordinary invalid results from reporting/commit authority loss after an effect. Version or missing progress alone cannot establish origin.

## Closed fact and reader contract

Extend the existing fact2/receipt2 family with ending `interrupted` and recovery exactly `{reason: "interrupted", attempts: int|null, restarts: int|null}`. Counts require exact nonnegative safe integers. Attempts come from validated committed progress; absent or unknown remains null. Restarts are the current task's checkpoint/state-local scheduler observation, captured at the recovery decision before checkpoint reset; they are not a cumulative total. Only absence of the task-record restart source maps to null; this does not relax the receipt shape. Every interrupted receipt must contain all three recovery keys, including explicit null values where unknown. Every reader refuses a missing recovery key. For receipt-absent recovered execute, a present float, boolean, negative or unsafe source counter causes fixed incompatible refusal in public preflight before scheduler execution or task, entry or header writes. The execution classifier revalidates that actual source before new receipt/result mutation or safe replay. An actual valid saved receipt takes precedence and settles unchanged using its saved counters, regardless of later current restart metadata; unrelated live parent/provider rows do not acquire this counter policy. Invalid source values are never converted to null or zero. Existing stored prefix counters remain historical observations, never substituted for current scheduler state.

The ToolExecutionOutcome has cancelled and malformed_arguments false, interruption SETTLED and execution_seconds null; its AgentToolResultMessage has is_error true and terminate false. The dedicated durable cause represents uncertain execution, without adding a waiter/operator enum member. Preserve raw retained output, details and diagnostics. Model projection appends `Tool execution interrupted; result is uncertain.` through the existing harness wrapper. The child ends raw FAILED with exactly this message, never a tool_error category.

Writer, ending validation, projection, receipt parser and every result reader must agree on cause, counters, controls and terminal message. Preserve one actual saved receipt carrier, one canonical arena and all CID/call/task/slot/byTaskId proofs. Private intent, arguments, key and workspace remain absent from public metadata, completed output and provider wire. Existing fact1 and B fact2 bytes/acceptance remain unchanged.

## Acceptance and documentation

Use actual public SDK cold resume and CLI cuts: execute committed before invocation and after one effect; unchanged unsafe; stored-safe/current-missing, unsafe or changed declaration/version; unchanged-safe replay; receipt/progress committed before lost ACK; repeated terminal reopen without duplicated preparation, effect or usage. Assert the actual next provider request, narrowed ordered catalog and answer. Separately cut after child creation before intent, and during an old persisted provider request, then remove a tool: preflight must refuse with no state mutation, new permanent hold, preparation or effect; restoring the catalog must remain usable. Add a mixed-catalog cut with a safe replay pending and an unrelated tool removed: it must refuse before writes even though the pending tool itself is unchanged. Inject present-invalid task source counters and assert the same mutation-free preflight refusal; remove each required recovery counter key independently and require fixed refusal through every reader.

Cover all historical blocked origins and receipts, including an actual older-B receipt round trip, as held controls. Mutate new cause/counter/control/owner/reference fields through real readers; retain completing safe-skip, old fact controls and private-marker negatives. SIGKILL process-group evidence is not arbitrary orphan cleanup or exactly-once execution.

Update release notes and durable-tools, durable-inspection, SDK, completed-projection, recovery/product/headless usage and current plan/evidence documentation in the same change. State the C1/C2 split and narrow public catalog exception explicitly. Focused physical/SDK/CLI tests, supported runtimes, source-closed comparisons, rendered docs, full checks and independent code review gate delivery. The whole-implementation review must include this contract and its executable mixed-catalog, source-counter and missing-receipt-key tests; standalone plan review does not establish these behaviors. DE14 retains restart ceilings/parking/reset; C1 makes no unlimited-retry promise. C2, P15/P16 and broader cleanup/storage/resource obligations remain open.
