## Scope and private API

Add `TaskScheduler.install_definition(task: Task) -> bool`, `ainstall_definition(task: Task) -> bool`, `remove_definition(name: str) -> bool`, and `aremove_definition(name: str) -> bool`. The boolean acknowledges whether the current definition generation changed. These are private owner controls, with no Product, public SDK/CLI, extension registry, subscription or listener surface. Publication itself performs no Storage commit, task migration, initializer/handler call, task/document/header mutation, counter reset, or scheduling enable.

Installation inserts an absent UTF-16 name or explicitly replaces that name with a different Task identity. It preserves existing name position; new names append. Same unchanged source Task is a no-change ACK. Removal of an absent valid name is a no-change ACK; removal of a present generic name changes the generation. No aliases or batch merge API. The exact reserved names `pi.generation`, `pi.tool`, and pinned Pi's `pi.compaction` refuse installation/removal through these controls, even if absent or identical. This does not add a compaction implementation or strengthen existing constructor semantics. Names use existing exact-string/UTF-16 identity rules; finite version ABI remains unchanged, including negative/fractional/signed-zero values.

## Identity and failure memo ownership

Keep a private immutable binding of **original exact Task object** and **captured Task**. Constructor registration establishes these bindings before the owner becomes visible. An unrelated publication reuses every unchanged binding and captured object; rebuilding the entire catalog through `capture()` is forbidden.

After existing reentry and synchronous off-loop refusal, capture and validate an incoming exact Task before the first suspension. A source object is known only while installed or retained by a live failure memo. On the accepted Session line, compare that early captured snapshot with the retained binding, without rereading the mutable source object. A known source must match its original captured declaration: exact owned name/version/ordered phase keys/support data and callback identities (`is`, never callback equality). A valid changed snapshot of the same known source raises ValueError; an intentionally changed declaration requires a new Task object. Invalid capture leaves the old generation untouched. Equal UTF-16 name identity follows the stated replacement rule, not a separate collision refusal. Comparison/copying occurs outside the condition without invoking handlers or arbitrary equality hooks.

The existing one-failure-per-live-task cache retains a definition binding, not just a replaceable name/version. Failure matching is by original source Task identity with its stable capture. Same-source reinstall, unrelated publication, and remove→reinstall the same failed Task do not retry migration. Removal does not clear that failure memo. A different Task object may retry even when its name/version/callbacks are otherwise equal. A later failed replacement may overwrite that task's single memo; terminal publication and owner retirement discard it as today. Thus removing/readding an older source after another failure may retry, matching the single-memo model. No permanent registry-wide history or unbounded per-replacement identity table is introduced: retained bindings are current entries plus existing per-live-task failure entries. Displaced references are released outside the condition.

Pi retains source Task objects directly, while native capture owns data. The identity bridge preserves the relevant Pi cache behavior without weakening native snapshots. Pi remove/readd preservation is a source inference conditional on no intervening terminal/cache overwrite, and must become an executable native control here.

## Publication and shared readers

Use one immutable generation containing the ordered bindings/definition lookup and callback-free InspectionSupport. A publication runs on the existing Session line, then takes the actual owner condition. Never hold the condition while acquiring/waiting for the line. It validates health/close/open and **both `_draining is False` and `_invocation is None`** at the publication point. The condition also guards service admission to draining, so no reservation, migrator, active invocation, or admitted drain may overlap replacement. An earlier pause/inspection result is not authority. A busy owner raises RuntimeError. Enabled-owner publication is best-effort: an independently admitted drain, including one caused by a preceding publication wake, may win and cause refusal. There is no automatic retry, new wait-idle API, deferred install or active handover. Deterministic queued no-lost-update witnesses use a paused, actually quiescent owner; enabled witnesses distinguish accepted publication from a drain that already won admission. A successful ACK remains real even if its wake admits later work.

Prepare the next immutable generation outside the condition while owning the line, then recheck lifecycle/activity under the condition and publish by one pointer assignment. Serialize competing installs/removes through the line; derive each candidate from the generation current on that line, avoiding lost updates. No user code, callback disposal, Future completion, or notification occurs inside the condition. A refusal or preparation failure leaves generation, cache, support, scheduling state and durable tables unchanged.

All generation readers share the same ownership discipline: reservation captures one generation on the Session line for the whole pass, including built-in tool support checks and fitting; owner inspection captures generation, current policy and matching failure memo together inside its existing line read; resolution captures its support generation **inside the committing `change` job**, after the durable saved-winner early return and applicable actual metadata gates, before branch validation uses support. Remove its pre-commit support capture. A publication between preliminary `_metadata` and commit must therefore be observed; a saved winner still returns without current-catalog dependence. Terminal/completing inspection keeps its callback-free no-code path. Ordinary standalone InspectionSupport/inspection remains a caller-owned snapshot and does not become a live scheduler view. Previously returned DTOs and retained generation/support snapshots remain stable after publication. No new DTO field or public export is needed.

## Lifecycle, notification and cancellation

Use the actual b2 order, not a new lifecycle flag: (1) existing reentry refusal and, for synchronous calls, off-loop refusal; (2) detached exact-Task capture or name validation, including reserved-name refusal, before any asynchronous suspension; (3) accepted line health/failure, sealed/host-done close, then actual `_opened`; (4) compare the early capture with a known retained binding, raising ValueError for valid changed authority; (5) require no admitted drain/invocation, otherwise RuntimeError. Invalid capture/name uses existing TypeError/ValueError, so it can precede closed/failed lifecycle refusal after the initial reentry/off-loop checks. A valid changed known source reaches the line and therefore cannot override earlier lifecycle failure. Valid absent-name removal still passes health/open/activity gates before returning false without a wake. `_opening` is sticky and cannot establish readiness. Never auto-open/recover; SessionFailed/SessionClosedError remain private outcomes and public retry/errors remain unchanged.

A successful installation, including an identical-source no-change ACK, requests one existing owned wake **only if enabled and healthy**; a changed removal does the same. Absent removal requests no wake. Publication never enables a paused owner. Notify after releasing the condition; close winning afterward may absorb that wake. ACK means metadata publication/no-change, not dispatch, migration success, graph idle or completed work. An enabled wake may later cause legitimate reconciliation/dispatch writes; those are not publication writes. This narrowly follows Pi's same-object install notification and absent-uninstall behavior without copying listeners or claiming general registry parity.

Async cancellation joins the real accepted Session-line job through existing `owned_call`; it does not roll back a published generation or cancel an admitted successor pass. Close/failure ordering is determined by existing line/lifecycle admission, not a new mirror flag. Test cancellation before admission, held publication, and after assignment; retain the actual returned/cancelled outcome and resulting generation. A close after assignment may prevent subsequent dispatch while the published decision remains real. No arbitrary listener exceptions or rollback promise: Pi assigns current before invoking listeners, but this child has no listeners.
